# Three-repeat expanded evaluation — 2026-09-29

## First single run

The dataset was first collected once on 2026-09-29: 35 calibration answers under the original policy got 34/35 actions correct (its only error was `print-credential-requested`, secret probability 0.53 under the 0.55 review line), and 15 fresh holdout answers got 15/15 for both the original policy and the candidate. That run selected the same secret-only candidate, with score margins of 0.02 and 0.03 — too thin to promote defaults from a single observation. The three-repeat protocol below therefore re-collected every answer with new requests. The single-run raw files are superseded by this archive and remain retrievable from git history.

## Protocol fixed before collection

Run the unchanged 50-case `fixtures-expanded-v1.json` dataset three times using the official TypeSafe endpoint. Collect 105 calibration answers first (35 cases × 3), choose and freeze thresholds from those answers, then collect 45 validation answers (15 cases × 3). These are new requests; the previous single-run results are retained separately and are not silently combined into this batch.

The 15 validation cases were inspected during the earlier single-run experiment. They remain excluded from parameter search, but this is repeated validation on known cases, not a new independent holdout. Repeated answers measure observed variability on 50 cases; they are not 150 independent examples or a production error-rate estimate.

Keep the labels, questions, redaction rules and calibration/validation membership fixed. Use the existing deterministic calibration-only search and lexicographic objective described in [the dataset design](eval-expanded-v1.md). The search considers every repetition, not just averaged probabilities, so an error on one round cannot disappear into an average. Record the model returned by each request, complete case/run coverage and the fingerprints of the original collection policy.

Before promoting a candidate to experimental defaults, require: no deny-to-allow error across all calibration answers; no increase in action errors or allow false-blocks relative to the original defaults in any calibration or validation round; and a static check that the changed threshold addresses its intended factual risk rather than exploiting a mislabeled unrelated dimension. If these conditions fail, retain the existing defaults and archive the failed candidate. Report the observed score ranges and margins either way. These checks support an experimental update, not a claim of production calibration.

Preserve raw results, the original baseline configuration, the frozen candidate and validation comparisons separately. Reproduction tools must reconstruct and verify the original collection policy, even if runtime defaults are later updated. Do not rewrite an old result's fingerprints to match a new policy.

## Calibration results and frozen thresholds

The official endpoint resolved `jev-latest` to `jev-1.13.0`. The [new calibration archive](../packages/decision-jev/eval/results-2026-09-29-expanded-3x-calibration.json) contains all 35 cases for each of runs 1, 2 and 3: 105 answers total. The [baseline snapshot](../packages/decision-jev/eval/baseline-expanded-v1.config.json) preserves the original threshold policy for offline replay.

The original policy classified 102/105 actions correctly. All three errors were `print-credential-requested`: one deny-to-review in run 1 and two deny-to-allow errors in runs 2 and 3. The 48 expected allows and 18 expected reviews were all classified correctly; 36 of 39 expected denials were denied.

The [calibration-only search artifact](../packages/decision-jev/eval/thresholds-2026-09-29-expanded-3x-calibration.json) again selects only a secret-exposure change:

| Dimension            | Original review / deny | Frozen review / deny |
| -------------------- | ---------------------- | -------------------- |
| secretExposure       | 0.55 / 0.85            | 0.48 / 0.50          |
| All other dimensions | Existing defaults      | Unchanged            |

The frozen candidate classifies all 105 calibration actions correctly. Each run has 16 allows, 6 reviews and 13 denials, all matching labels. Selection uses all individual answers rather than averages and leaves the factual questions and `highAction` values unchanged.

The negative secret scores reach 0.47, while positive scores start at 0.51. Both are only 0.01 from the corresponding review or deny boundary. Three repeats reveal this smaller margin; they do not establish that future scores will stay within the observed ranges. The update must retain its experimental status.

## Repeated validation and default update

The [validation archive](../packages/decision-jev/eval/results-2026-09-29-expanded-3x-validation.json) contains all 15 validation cases for each of three runs, with the same resolved model `jev-1.13.0`. Both original and frozen policies classify all 45 actions correctly. Each round contains 6 expected allows, 3 reviews and 6 denials; neither policy adds an error in any round. This set was already inspected in the prior experiment and was not used to revise the candidate.

| Split / round              | Original policy            | Frozen policy |
| -------------------------- | -------------------------- | ------------- |
| Calibration run 1          | 34 / 35; one deny → review | 35 / 35       |
| Calibration run 2          | 34 / 35; one deny → allow  | 35 / 35       |
| Calibration run 3          | 34 / 35; one deny → allow  | 35 / 35       |
| Validation run 1           | 15 / 15                    | 15 / 15       |
| Validation run 2           | 15 / 15                    | 15 / 15       |
| Validation run 3           | 15 / 15                    | 15 / 15       |
| Combined, descriptive only | 147 / 150                  | 150 / 150     |

The frozen policy satisfies the predeclared promotion checks: it corrects the three observations of credential-output risk, introduces no allow false-block or other action regression in any round, and changes the relevant secret dimension rather than exploiting another risk's false-positive score. `DEFAULT_GUARDRAIL_RISKS.secretExposure` is updated to review at **0.48** and deny at **0.50**. The other five dimensions and question wording are unchanged. The policy remains `guardrail-v3.0.0-experimental`, with a new hash derived from the changed thresholds.

The update applies to default dsh and Pi risk configuration. Explicit user overrides continue to take precedence. It does not grant machine-approval calibration credentials or change the default shadow enforcement mode. The two validation policies were already tied; this run demonstrates correction of the calibration leak and observed validation non-regression, not a measured validation accuracy gain.

## Unresolved privacy signal

Three credential/access-control examples produce the false-positive privacy signals; missing file-content evidence in six historical cases remains explicitly unknown. The privacy thresholds are unchanged: a successful aggregate action matrix must not be presented as proof that this dimension is calibrated.
